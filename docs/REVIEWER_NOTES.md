# Notes for AMO reviewers

Submitted package: `sankaku-firefox-mv3-<version>.zip` (Manifest V3, Firefox 128+).

## What the add-on does

It adds quick actions to <https://www.sankakucomplex.com> — an image board the
user is already logged into:

- rating stars and the favorite heart become clickable in the post grid and in
  the viewer, so the user does not have to open every post;
- keyboard shortcuts on the post page (1–5 rate, F favorite, C comments,
  E emotion);
- optional badge showing the rating the user gave;
- a bulk upload page that fills the site's own upload form for several files;
- optional hiding of ads and of the site's "Sankaku Plus" reminders;
- counters for site points and reputation next to the existing menu button.

Everything happens on that one site, with the user's own session. Nothing is
unlocked, no paid feature is bypassed: the "Plus" reminders are only hidden
from view, exactly like an ad blocker hides banners.

## Data

The add-on collects and transmits nothing. The only storage used is
`browser.storage.local`, which holds the user's settings (checkboxes, delays,
hotkey codes). The manifest declares `data_collection_permissions: {"required":
["none"]}`. There is no analytics, no telemetry, no remote endpoint of our own.

## Why the page context is used

`core-main.js` runs as a content script with `"world": "MAIN"`. It has to,
for two reasons:

1. The site is a React application. The add-on reads post data from React props
   to know which post a card belongs to.
2. The add-on wraps the page's own `fetch`/`XMLHttpRequest` to read responses
   the site already requests (post lists) and to reuse the site's own
   `Authorization` header when the user clicks a star or a heart. The requests
   go to the site's own API (`sankakuapi.com`), the same one the page itself
   calls. No credentials are read, stored or sent anywhere else.

`bridge.js` runs in the isolated world and does only three things: reads and
writes settings in `browser.storage.local`, passes them to the page through
`CustomEvent`s, and relays the toolbar button click. `background.js` only
forwards that click to the active tab.

No remote code is loaded or executed. Everything that runs is inside the
package.

## How the package is built

Python 3.12, no third-party dependencies, no network access needed:

```bash
python build.py --zip
```

`dist/firefox-mv3/` is the submitted add-on, `dist/sankaku-firefox-mv3-<version>.zip`
is the same folder zipped.

Mapping between the sources and the files in the package:

| File in the package | Built from |
|---|---|
| `core-main.js` | `src/core.js` wrapped in an IIFE, with the translation tables from `src/i18n/*.json` inlined in place of the `{{I18N}}` marker |
| `bridge.js` | `src/ext/bridge.js`; `{{INJECT_CORE}}` becomes `false` and `{{CORE_SRC}}` becomes `null` for this build |
| `background.js` | `src/ext/background.js`, unchanged |
| `manifest.json` | `src/ext/manifest.firefox.json` with `{{VERSION}}` replaced |
| `icons/*.png` | generated by `build.py` (`star_png`), a plain orange square with a white star |

The only generated part is the translation table: 155 strings in 26 languages,
assembled from `src/i18n/base.json` (key order and English) and
`src/i18n/lang_<code>.json`. Nothing is minified or obfuscated; the built file
is the source with those strings pasted in.

The same `src/core.js` is also published as a Tampermonkey userscript, which is
why the code is written to run both from a userscript loader and from a content
script.

## Testing

A logged-in account on the site is required for rating, favoriting and
uploading; the grid, the settings and the hidden-preview features work without
one. Test credentials are provided in the submission form.

Suggested check: open the site, hover a post card, click a star — the rating is
sent and the stars update. The add-on's settings open from the toolbar button,
and on the site's own settings page they also appear as a "Plugin" tab.
